# AI 協同設計工作流

## 觸發
`/design-workflow`、`[設計流程企劃]`、「這套系統怎麼用」

## 分工原則

| 工具 | 負責 | 不要用它做 |
|---|---|---|
| **Claude Code（本專案）** | 大數據調研、15 年庫存比對、波段企劃邏輯、Tech Pack 文字規格、統計關聯分析、以圖反查貨號 | 生成彩現效果圖 |
| **ChatGPT / Firefly / Midjourney** | 視覺概念轉化、線稿 prompt 出圖、快速視覺提案、配色模擬 | 數據判斷、庫存比對 |
| **設計師本人** | 最後的美感決策、版型微調、品牌調性把關 | 手工比對 450 款的歷史數據 |

系統負責把骨架排出來、把證據攤開；人負責決定要不要採用。這個分界不要模糊。

## 完整流程

```
① 資料備妥      系統圖 / 裁縫指示書 / POS / 市調圖 放進 data/raw/
                  ↓  python -m chainway.cli doctor
② 匯入與特徵    ingest → embed
                  ↓
③ 合併與分級    build      （產出主表、暢銷/滯銷分級）
                  ↓
④ ★ 填市場回饋  業務/門市填 sales_feedback.csv 或用網頁後台
                  ↓  這一步不做，就只知道「賣不好」，不知道「為什麼」
⑤ 分析與診斷    analyze    （關聯報告 + 真/假滯銷診斷）
                  ↓
⑥ 版型研究      版型甜蜜區間 → 發給版師當打版目標值
                  ↓
⑦ 系列企劃      plan --week N  （每週 10–15 款骨架）
                  ↓
⑧ 市調轉線稿    sketch     （市調圖 → 線稿 / 彩現 / 色票）
                  ↓
⑨ 機械圖        /draw-flats → 規格書 + 英文 prompt → 交生成式繪圖或版師描稿
                  ↓
⑩ 上市後回頭做 ④，形成閉環
```

## 每季固定節奏建議

| 時間 | 動作 | 指令 |
|---|---|---|
| 季末 +2 週 | 匯入該季 POS，重跑分析 | `ingest → build → analyze` |
| 季末 +3 週 | 發回饋表給門市，收回填寫 | `feedback template` |
| 季末 +4 週 | 交叉診斷會議 | 看報告第五節「衝突」與「假滯銷」 |
| 開發期 | 每週產出企劃骨架 | `plan --week N` |
| 隨時 | 市調圖轉線稿 | `sketch --image X --auto` |

## 提醒

- 第 ④ 步是整套系統的成敗關鍵。沒有市場回饋，所有結論都只是相關性，
  分不出「設計不好」和「東西根本沒被看到」。
- 任何結論引用時一律附樣本數。n < 20 說「假設」，不說「結論」。
