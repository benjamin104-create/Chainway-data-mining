## 模組職責

| 模組 | 檔案 | 職責 |
|---|---|---|
| 設定 | `chainway/config.py` | 全專案唯一知道檔案在哪的地方 |
| 匯入 | `chainway/ingest/` | 四種原始資料 → 統一 DataFrame，含匯入稽核 |
| 特徵 | `chainway/features/` | Fashion-CLIP 向量、zero-shot 屬性、版型比例 |
| 合併 | `chainway/merge/` | 四方 left join + 命中率稽核 |
| 分析 | `chainway/analysis/` | 績效分級、關聯、版型研究、★診斷 |
| 檢索 | `chainway/search/` | 以圖/以文反查貨號與價格 |
| 企劃 | `chainway/planning/` | 年度波段、週度 10–15 款、組套 |
| 線稿 | `chainway/sketch/` | ★ 裁切、線稿、向量化、彩現、標註、機械圖 prompt |
| 報告 | `chainway/report/` | HTML + Excel |
| 介面 | `chainway/cli.py` `apps/` | CLI 與網頁後台 |

## 幾個關鍵設計決定

**為什麼用 left join 而不是 inner join？**
沒有系統圖的貨號仍要留在表裡。用 inner join 的話，你會誤以為
「有拍照的商品比較好賣」—— 其實只是拍照的都是主推款。這叫選擇偏誤。

**為什麼績效分級要在「同季別 × 同品類」內做？**
冬天大衣的絕對銷量永遠比不上夏天 T 恤。全公司一條線切下去，
會得到「冬季外套全部滯銷」這種沒有意義的結論。

**為什麼要做多重檢定校正（BH-FDR）？**
跑幾百個「特徵 × 品類」組合時，即使全是隨機資料，
也會有 5% 的組合「達顯著」。不校正的話，報告會充滿假發現。

**為什麼屬性標註要保留 confidence？**
CLIP 分不出來的時候會硬猜。低信心的標註拿去跑統計，
你會得到「看起來很顯著、其實是模型在猜」的結論。
所以 confidence 低於門檻的一律標為 `uncertain` 並排除在分析外。

**為什麼版型分析用「比例」而不是「絕對公分數」？**
絕對尺寸受尺碼影響（S 碼的衣長當然比 L 碼短），跨款不能直接比。
胸腰比、擺胸比、肩胸比這種無單位的比例才能跨款、跨品類比較。

**為什麼需要人工回饋表？**
純數據只知道「賣不好」，不知道「為什麼」。
缺貨造成的滯銷跟設計失敗造成的滯銷，處置方式完全相反 ——
前者要追單，後者要停產。分不出來的話，這套系統會讓你做出錯誤決策。

## 部署

單機即可。公司內部要多人用的話：

```bash
python -m chainway.cli serve --host 0.0.0.0 --port 8000
```

資料留在該台機器，不外傳。若要放到公司內網伺服器，
把 `data/` 指向 NAS 共用路徑即可（`settings.yaml` 支援 UNC 路徑）。

**注意**：目前沒有登入機制，僅適合內網使用。
需要對外時請加反向代理與驗證，不要直接曝露。
