# 通天鬥塔 Siege of Mysteries — 設計文件

橫向單線推塔（鬥塔）動作遊戲。主角沿用先前設計的橘色黏土球戰士，
故事以七個世界謎團延伸，重心放在**職業養成、視覺化技能樹、技能欄切換**，
武器防具買賣作為輔助系統。

程式位置：`apps/game/`，開啟 `apps/game/index.html` 就能玩，沒有任何建置步驟。

---

## 一、核心迴圈

**俯視平面地圖**，整張戰場一次看完，不捲動。一條蛇行的石板路從左下的我方城門
一路繞到右上的敵方主塔，路上有一到兩座哨塔，路邊散著僱用所。

| 元素 | 規則 |
|---|---|
| 勝利 | 摧毀敵方主塔 |
| 失敗 | 我方城門被推倒 |
| 部署階段 | 開打前先點地圖上的據點擺好人，按「開戰」才開始 |
| 英雄 | 沿路前後移動、自動普攻、四個技能欄、兩種消耗品 |
| 僱用所 | 路邊的據點，用當場賺到的金幣僱機械 / 武具 / 傭兵 |
| 小兵 | 雙方每隔一段時間自動出兵，波次愈後人數愈多 |
| 塔 | 會對射程內的敵人射擊；主塔在哨塔全倒之前無敵 |
| 封鎖線 | 哨塔還活著時，英雄無法越過該塔前方 230 單位 |

### 俯視是怎麼做的

戰鬥模擬**完全沒有改成 2D**。實體的 `x` 仍然是「從城門沿路走了多遠」，
`z` 仍然是左右偏移；只有繪製的時候才把 `(x, z)` 投影到那條蜿蜒的路徑上
（`js/core/map.js`）。這樣所有既有的射程、行軍、封鎖線、僱用所判定都原封不動成立，
換來的是整個戰場一眼看完的呈現。

路徑由關卡代號決定種子，蛇行三到四排，裝飾物散在路徑外側至少 58 像素處。
所有會互相遮擋的東西（裝飾、據點、塔、單位）一起依畫面 y 排序後再畫，
做出俯視的前後關係。

三個設計決定撐起「鬥塔」的手感：

1. **我方小兵對建築物造成三倍傷害。** 推線本身就是拆塔的手段，
   英雄不是唯一的輸出來源，而是決定哪一邊先破的那一票。
2. **拆掉一座塔，敵方出兵量等比下降。** 推進即防守，戰局會隨戰況傾斜，
   不會永遠僵持在中路。
3. **英雄死亡不等於失敗。** 六秒後從城門重生，線還在，只是你不在。

## 二、章節：七個世界謎團

每章三關（前庭 / 內廊 / 核心），核心關有頭目。背景剪影、配色、敵人組成依章節切換，
背景是程序生成的三層視差，不使用外部圖檔。

| # | 章節 | 謎題 | 頭目 |
|---|---|---|---|
| I | 巴別之塔 | 語言為什麼散了 | 眾聲之口 |
| II | 吉薩星門 | 三座金字塔對準獵戶座腰帶 | 無面之獅 |
| III | 納斯卡地紋 | 只有從天上才看得懂的畫 | 蜂鳥 |
| IV | 亞特蘭提斯 | 一夜之間沉下去的城 | 潮位官 |
| V | 復活節島 | 會走路的石像 | 未完成的巨人 |
| VI | 百慕達漩渦 | 指北針指向哪個北方 | 第十九中隊 |
| VII | 巨石陣：時鎖 | 一年只對準兩次的鐘 | 夏至 |

每章的敘事都收在同一個角度：**謎團之所以留下來，是因為有人需要它留下來。**
納斯卡線那章講「有些事要離得夠遠才看得出形狀」，復活節島那章講
「傳說沒騙人，只是省略了那條繩子和拉繩子的所有人」。

## 三、職業與技能樹（核心系統）

四個職業，各自一張 13 節點的路徑圖，五個階層。
圓形節點是主動技能，方形是被動；連線畫在 SVG 上，學會的路徑會亮起職業色。

| 職業 | 定位 | 解鎖條件 |
|---|---|---|
| 掘徑者 Delver | 近戰推進，血厚、攻城傷害最高 | 一開始就有 |
| 石語者 Stonespeaker | 遠程法術，清場最強、單體最弱 | 通關 巴別之塔 · 核心 |
| 縛影者 Shadowbinder | 刺客，位移多、暴擊爆發極高、血最少 | 通關 納斯卡地紋 · 核心 |
| 燈守 Lampwarden | 召喚支援，本體最弱但整條線最強 | 通關 亞特蘭提斯 · 核心 |

### 技能點是共用的

`SP` 是一個總量，每個職業**各自**從這個總量分配。
換職業不會失去任何進度，也不需要重練——這是為了讓「切換職業」成為真的選項，
而不是懲罰。每個職業都能隨時重置，點數全額退回。

一輪完整通關大約累積 43 點，而點滿一棵樹需要 22 點以上，
所以一輪玩不滿所有職業，這是刻意的。

### 技能欄

四格，對應鍵盤 `1`–`4`。只要學會的主動技能都能隨時換進換出，
在技能樹頁面先點欄位、再點技能即可。被動學會就永久生效。

技能型別共十二種，都已實作：扇形近戰、投射物、地面範圍、位移、
自身/團隊增益、召喚、治療、貫穿光束、設置石壁、設置砲塔、引導旋轉、連續瞬移。

被動用旗標（flag）掛在戰鬥邏輯上，例如：
擴散攻擊、灼燒、斬殺、反傷、背刺必暴、暴擊減冷卻、擊殺重置位移、
站著不動加傷、技能連鎖觸發、小兵死亡爆炸、小兵光環。

## 四、戰場僱用（機械 / 武具 / 傭兵）

地圖上散佈著幾個**僱用所**：城門附近一個，每座敵塔前方各一個，畫成路邊的木造據點。
用的是**當場賺到的現場資金**，不是倉庫裡的錢。

有兩個時機可以僱用：

- **部署階段** — 開打前，點地圖上亮起的據點，在那裡直接擺人。
  超過封鎖線的據點還到不了，不能部署。
- **戰鬥中** — 把英雄走到據點旁邊（120 單位內），面板就會跳出來。
  這時武具會架在英雄腳下，所以拒馬擋在哪裡是你當下的判斷。

每個據點提供三件，傭兵 / 機械 / 武具各一。越深處的據點貨色越好也越便宜，
但要先把前面的塔拆掉才走得到——「要不要冒險走到第三個據點」是一個真的決定。

| 據點 | 傭兵 | 機械 | 武具 | 折扣 |
|---|---|---|---|---|
| 僱用所・壹 | 傭兵 | 攻城車 | 拒馬 | — |
| 僱用所・貳 | 魔法師 | 彈弩台 | 火油槽 | 8% |
| 僱用所・參 | 白魔道士 | 鑽地機 | 戰旗 | 16% |
| 僱用所・肆 | 傭兵 | 彈弩台 | 戰旗 | 20% |

九個僱用對象各有不同的戰鬥行為，不是換皮的數值：

- **傭兵** — 近戰，跟著推進線往前打。
- **魔法師** — 遠程，攻擊在命中處炸開（濺射），對成群的敵人特別有效。
- **白魔道士** — 完全不攻擊，持續回復範圍內血量最低的友軍，包含你自己。
- **攻城車** — 很慢很厚，對建築物七倍傷害，對人只有三成。專職拆塔。
- **彈弩台** — 射程 245、單體傷害高，但射速只有一般單位的六成。
- **鑽地機** — 邊前進邊震地，每 0.7 秒對周圍造成一次範圍傷害。
- **拒馬** — 真的會**擋住**敵人推進：已經在它右邊的敵人過不去，
  而且被擋住的敵人會轉頭拆它，所以不會變成無限卡位。
- **火油槽** — 定點，每 0.4 秒燒灼範圍內的敵人。
- **戰旗** — 光環：範圍 230 內的友軍（含英雄）傷害 +30%、移速 +15%。

### 為什麼用現場資金

因為花掉的錢**不會跟你回家**。結算時帶回的是「戰場收入 − 僱用支出」。
所以每一次僱用都是同一個取捨：**現在贏，還是之後買得起更好的裝備。**

模擬顯示這個取捨是真的：把錢全部花在僱用上的機器人，
21 關全部一次過關，但到最後只買得起潮位三叉，摸不到至日之石。

## 五、商店

三個裝備欄（武器 / 防具 / 遺物）各九件，依關卡進度解鎖。
買過的永久保留，可以隨時換回來。另有兩種戰鬥消耗品（油罐、火藥包）。

每件裝備都有一句與該章謎團有關的說明文字，例如摩艾拳：
「十噸的石頭，靠左右搖晃就能走路。」

## 六、平衡驗證

用 Playwright 開無頭瀏覽器，直接驅動戰鬥模擬（不經過畫面更新），
讓一個貪心機器人照著真實進度打完全部 21 關：贏了才拿獎勵、
用賺到的金幣買得起的最貴裝備、把技能點花掉、血低於三分之一就後撤。

最近一次完整跑分（每關最多重試四次，機器人會把買得起的僱用全部買下去）：

| 關卡 | 職業 | 嘗試 | 秒數 | 等級 |
|---|---|---|---|---|
| 巴別 1–3 | 掘徑者 | 1 / 1 / 1 | 117 / 135 / 262 | 3 |
| 吉薩 1–3 | 石語者 | 1 / 1 / 1 | 73 / 93 / 72 | 6 |
| 納斯卡 1–3 | 石語者 | 1 / 1 / 1 | 77 / 164 / 192 | 7 |
| 亞特蘭提斯 1–3 | 縛影者 | 1 / 1 / 1 | 66 / 122 / 277 | 9 |
| 復活節島 1–3 | 燈守 | 1 / 1 / 1 | 46 / 55 / 64 | 11 |
| 百慕達 1–3 | 燈守 | 1 / 1 / 1 | 60 / 85 / 84 | 11 |
| 巨石陣 1–3 | 燈守 | 1 / 1 / 1 | 221 / 215 / 258 | 13 |

21 關全數通關，無主控台錯誤。機器人打得比人差（它只會一直往前衝），
所以這組數字可以視為難度上限。

調校過程中靠模擬抓到四個靠讀程式看不出來的問題：

1. 頭目會一路走到你家城門，而不是守塔 → 加上 leash。
2. 英雄可以繞過哨塔，卡在無敵的主塔前面空轉 → 加上封鎖線。
3. 我方小兵的成長曲線比敵方慢，第三章之後整條線被輾過去 → 改用同一條縮放曲線。
4. 血量低了以後沒有任何回復手段，形成死結 → 加上脫離戰鬥回血。

## 七、程式結構

```
apps/game/
  index.html            進入點（body-only，可直接開，也可當 Artifact 發佈）
  css/game.css          全部樣式
  js/data/chapters.js   七章資料、敵人原型、21 關生成
  js/data/classes.js    四職業、52 個技能樹節點、技能定義
  js/data/items.js      27 件裝備、2 種消耗品
  js/data/hires.js      9 個戰場僱用對象、4 種僱用所配置
  js/core/state.js      存檔（localStorage）、等級、技能點、數值結算
  js/core/map.js        俯視地圖：路徑生成、世界座標 → 畫面座標投影
  js/core/battle.js     戰鬥模擬：AI、傷害、技能、波次
  js/core/render.js     Canvas 繪製：地形、路面、單位、特效、深度排序
  js/ui/icons.js        30 個線條圖示
  js/ui/screens.js      章節、職業、技能樹、商店、結算畫面
  js/main.js            啟動、事件路由、遊戲迴圈
```

全部使用傳統 `<script>` 標籤，沒有 ES module、沒有打包工具、沒有外部函式庫，
因此用 `file://` 直接開檔也能跑。字型從 Google Fonts 載入
（Cinzel 拉丁標題、Noto Serif TC 敘事、Noto Sans TC 介面、Silkscreen 數值），
離線時會退回系統字型。

存檔寫在 `localStorage`，讀寫都包在 `try/catch`，隱私模式下不會壞掉。

## 八、視覺方向

介面定位是「一台架在挖掘現場的燈下控制台」；戰場是俯視的沙盤。

每章除了氣氛色之外，另外指定了**地**與**路**兩組顏色，
刻意拉開明度差，否則俯視圖會整片糊在一起——第一版就是這樣，
路和地幾乎同色，看不出動線。

| 用途 | 色值 |
|---|---|
| 底色 | `#12100D` 墨棕 |
| 面板 | `#1B1712` / `#262019` |
| 釉磚藍（伊什塔門） | `#3C63B0` |
| 燈火赭金 | `#E0B23C` |
| 主角橘 | `#E07A3F` |
| 羊皮字 | `#E8DBBE` |

面板標題列用重複線性漸層做成釉磚帶，呼應巴比倫伊什塔門的藍磚。
刻意維持單一視覺世界，不跟隨系統淺色/深色主題翻面，
但所有顏色都明確指定，不依賴瀏覽器預設。
