# 在自己的電腦上執行

## 先講清楚一件事

`config/settings.yaml` 裡的路徑**已經設好了**：

```yaml
paths:
  root: "C:/Users/USER/Desktop/商品設計Raw Data"
```

這行跟你的資料夾位置完全相符（64.9 GB、91,705 個檔案、8,487 個資料夾）。

但這行字只是**一張紙條**，寫著「資料在哪」。真正去讀資料的是程式，
而程式必須跑在**放著那個資料夾的那台電腦上**。

我（Claude）是在雲端的容器裡工作，跟你的電腦之間沒有任何網路通道 ——
不管設定檔寫得多正確，我都碰不到你的 C 槽。同理，你在網頁上跟我對話時，
我也沒辦法「連進去」看那 91,705 個檔案。

**所以「串連」這件事，是把程式放到你電腦上執行，不是我這邊按什麼開關。**

---

## 最短路徑：三步

### 1. 把專案抓到你的電腦

在桌面按右鍵 → 開啟終端機（或 PowerShell），貼上：

```powershell
cd %USERPROFILE%\Desktop
git clone https://github.com/benjamin104-create/Chainway-data-mining.git
cd Chainway-data-mining
git checkout claude/fashion-sales-design-platform-vabg76
```

沒裝 git 的話，改用網頁下載：
GitHub 頁面右上角綠色 **Code** 按鈕 → **Download ZIP** → 解壓縮到桌面。
記得先把分支切到 `claude/fashion-sales-design-platform-vabg76`。

### 2. 安裝 Python

到 <https://www.python.org/downloads/> 下載安裝，
**安裝畫面第一頁務必勾選 `Add Python to PATH`**（沒勾的話後面每一步都會說找不到 python）。

### 3. 按兩下 `run_report.bat`（或中文捷徑 `執行報告.bat`）

就這樣。它會自己建環境、裝套件、檢查路徑、產生報告，
完成後直接開啟報告所在的資料夾。

第一次約 3–5 分鐘（在裝套件），之後每次幾十秒。

cd %USERPROFILE%\Desktop\Chainway-data-mining

## 拍照回推貨號：`run_search.bat`

`run_report.bat` 只用進銷存數字。要做「拍一張衣服照片，回推貨號、價格、
庫存」，按兩下 **`run_search.bat`**。

它會依序做六件事，全部自動：

1. 建立／沿用 Python 環境
2. 裝 AI 套件（PyTorch CPU 版 + Fashion-CLIP，約 700 MB）
3. 掃描系統圖與進銷存
4. 對每張系統圖萃取影像特徵並做屬性標註
5. 把銷售、影像、裁縫指示書合併成主表
6. 啟動網頁介面，自動開啟 <http://127.0.0.1:8000>

**第一次要 20–40 分鐘**，多數時間在下載與讀圖。之後每次幾秒就開得起來 ——
向量會快取，只有新款需要重算。

### 為什麼裝的是 CPU 版 PyTorch

預設的 `pip install torch` 會連帶下載約 2.5 GB 的 CUDA 函式庫，
沒有 NVIDIA 顯卡的話完全用不到。`run_search.bat` 指定了 CPU 專用來源，
下載量降到約 200 MB，速度差別在讀圖那一步（3,729 張約 5–15 分鐘）。

真的有 NVIDIA 顯卡想加速，改裝 CUDA 版即可，程式會自動偵測：
<https://pytorch.org/get-started/locally/>

### 網頁能做什麼

- **丟一張照片** → 回傳最相似的款，含貨號、系統圖、定價、投入／售出／剩餘、完銷率
- **打文字** → 「深藍色格紋百褶裙」也能搜
- **市調照片、競品圖、穿搭照** 都可以丟，不限自家系統圖

### 準確率怎麼確認

不要憑感覺。跑這個指令量給你看：

```powershell
.venv\Scripts\python.exe -m chainway.cli eval-search
```

它拿裁縫指示書裡的打樣照片當查詢 —— 那是同一件衣服的另一張真實照片，
貨號從檔名就知道，不需要任何人工標註 —— 看系統圖能不能被找回來，
輸出 Top-1／Top-5／Top-10 命中率與 MRR。

這把尺是實作無關的：任何一套以圖搜貨號的系統，只要吐出「查詢 → 預測貨號」
的清單，都能用同一個指令評分，數字可以直接比較。

## `doctor` 會告訴你什麼

這是路徑對不對的唯一判準。它會逐一列出五個來源資料夾：

```
✓ [來源] system_images    C:\...\系統圖              (3729 個檔案)
✓ [來源] tech_packs       C:\...\裁縫指示書           (3489 個檔案)
✓ [來源] pos              C:\...\銷售資料excel        (11 個檔案)
```

打勾就是找到了。出現 `← 不存在` 的話它會**自動列出根目錄底下實際的子資料夾名稱**，
你照抄進 `settings.yaml` 就好，不必自己猜。

POS 資料夾找不到時，它還會自動掃描整個根目錄找出長得像進銷存的 Excel，
直接把可以填的路徑印給你。

## 常見卡關

| 症狀 | 原因與解法 |
|---|---|
| `找不到 Python` | 安裝時沒勾 Add Python to PATH。重裝一次，記得勾。 |
| `POS 資料夾都不存在` | 資料夾改過名字。跑 `doctor`，它會列出實際名稱給你抄。 |
| 報告出來了但**縮圖 0 張** | 系統圖檔名不是 `貨號.jpg`。程式已支援前綴比對（`KA1583008-1.jpg` 也找得到），若仍是 0，把 `系統圖\KA158\` 底下的檔名截圖給我。 |
| YAML 解析錯誤，訊息裡有 `\U` | `settings.yaml` 的路徑用了反斜線 `\`。一律改成正斜線 `/`。 |
| 讀 `.xls` 報錯 | 舊版 Excel 格式需要 `xlrd`：`pip install xlrd` |

## 資料安全

程式對你的 `商品設計Raw Data` 資料夾**只讀不寫**。
不會修改、移動或刪除任何原始檔，也不會碰 `.agents`、`AGENTS.md`、`INDEX.md`
或既有的 Codex 設定 —— 你原本的工具照常運作。

所有產出（中繼檔、報告、資料集 JSON）都寫在專案內的 `data\` 底下，
而且已被 `.gitignore` 排除，不會上傳到 GitHub。
